# Кейс-задача № 2 — наследование классов

## Техническое задание

Написать тестовую программу, которая демонстрирует работу методов базового и производного классов.

Ответом на задачу является ссылка на репозиторий GitHub, в котором хранится программа, либо результат, переданный другим удобным способом.

## Решение

В программе реализованы два класса:

- `Employee` — базовый класс сотрудника с методами `arrive_at_work()` и `report()`;
- `Chief` — производный класс руководителя, который наследует метод `arrive_at_work()`, переопределяет `report()` и добавляет собственный метод `delegate_task()`.

В переопределенном методе `Chief.report()` используется `super().report()`: сначала выполняется реализация базового класса, затем выводится отчет о работе всего отдела. Тестовая часть создает объекты обоих классов и последовательно демонстрирует базовый, унаследованный, переопределенный и собственный методы.

## Выводы

- `Chief` наследуется от `Employee`, поэтому объект руководителя получает доступ к открытым полям и методам базового класса. Именно поэтому `chief.arrive_at_work()` работает, хотя этот метод отдельно в `Chief` не объявлен.
- У класса `Chief` нет собственного конструктора, поэтому при создании руководителя вызывается унаследованный `Employee.__init__()`. Поле `name` появляется и у обычного сотрудника, и у руководителя.
- Наследование работает только от родителя к потомку. Объект `Employee` не получает метод `delegate_task()`, объявленный в `Chief`. Вызов `employee.delegate_task()` завершился бы ошибкой `AttributeError`.
- Обратное утверждение неверно: объект `Chief` имеет доступ к доступным членам `Employee`, потому что производный класс расширяет базовый.
- Метод `report()` переопределён в `Chief`. Один и тот же вызов `report()` приводит к разному поведению в зависимости от фактического класса объекта — это пример полиморфизма.
- Вызов `super().report()` позволяет не копировать код родительского метода: руководитель сначала выполняет обычный отчёт сотрудника, а затем добавляет информацию о работе отдела.
- Собственный метод `delegate_task()` показывает, что производный класс может не только изменять унаследованное поведение, но и добавлять новые возможности.
- Базовый класс описывает общие свойства сотрудников, а производный — особенности конкретной роли. Такой подход уменьшает повторение кода и упрощает расширение программы.

## Запуск

Требуется Python 3. Запустите команду из корня репозитория:

```bash
python case-2-inheritance/main.py
```
